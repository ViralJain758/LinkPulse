# Changelog

## Unreleased

- **Security headers and dashboard CSP.** Every server response now has a locked-down CSP, `nosniff`, `X-Frame-Options`, COOP, `Permissions-Policy`, HSTS on HTTPS requests (`HSTS_MAX_AGE_SECONDS`), and `/api/*` is `no-store`; `X-Powered-By` is gone; the password and report pages can no longer be framed. The dashboard build adds a CSP `<meta>` tag (`script-src 'self'`, no inline script or eval, `connect-src` limited to its origin and `VITE_API_URL`), and `client/vercel.json`, `client/public/_headers` and nginx/Caddy snippets carry `frame-ancestors 'none'` and the other header-only protections. **Rebuild the dashboard (`npm run build`) and serve it with those headers.** Tokens remain in `localStorage`; see `docs/SECURITY-HEADERS.md` for the `HttpOnly` cookie follow-up. See [docs/SECURITY-HEADERS.md](docs/SECURITY-HEADERS.md).

- **Operations.** New [docs/OPERATIONS.md](docs/OPERATIONS.md). `GET /health` now runs a query against the database and answers `503` when it fails (it used to return `ok` unconditionally); `GET /health/live` is the no-database liveness probe. Logs are structured (JSON in production, `LOG_LEVEL`, `LOG_FORMAT`) and every request has an id, returned as `X-Request-Id`, included in `500` responses and on every log line of that request. Optional error tracking with `SENTRY_DSN` (Sentry-compatible, no new dependency; reports unhandled errors, rejections and uncaught exceptions without request bodies, headers, queries or IPs). `scripts/backup.sh` and `scripts/restore.sh` with documented restore steps. `server/Dockerfile` (Node 22 Alpine, non-root, healthcheck), and `docker-compose.yml` now runs `migrate` and `server` against Supabase. **The local Postgres (`db` service) is removed**: Supabase is the only database. **Behaviour changes:** the "email not sent" production warning no longer includes the recipient address; an uncaught exception now exits the process after reporting it.

- **Click retention.** The `clicks` table no longer grows forever. Raw clicks older than `CLICK_RETENTION_DAYS` (default 180, minimum 100, `0` = keep all) are rolled up into a new `click_rollups` table (clicks per link per day) and deleted in atomic batches, so lifetime click counts stay exact. Runs hourly on a long-running server; on Vercel a daily cron calls `/api/maintenance/purge-clicks` (set `CRON_SECRET`). `npm run clicks:purge` (with `--dry-run`, `--days N`) handles a large backlog in one go. New migration `..._click-retention` (adds `click_rollups` and a BRIN index on `clicks(clicked_at)`). **This deletes per-click detail older than the window**; set `CLICK_RETENTION_DAYS=0` before upgrading to opt out. Dashboard ranges (up to 90 days) and exports are unaffected.

- **Abuse reports and takedowns.** Public `/report` page (and `/report/<slug>`) with reason, details, optional reporter email, per-IP rate limit and a honeypot; a "Report this link" link on password pages. New **Admin** tab (admins only) with Reports, Links, Users and Activity views: take a link down, suspend an account, restore either, or dismiss a report, each with a reason and an audit-log entry. A taken-down link answers `410` "Link removed" and its owner cannot re-enable it; a suspended account is signed out everywhere and cannot sign in. Reports never act automatically. Grant admin with `npm run admin -- you@example.com`. New migration `..._abuse-and-moderation` (run `npm run migrate`), new `RATE_LIMIT_REPORTS_PER_IP` and `ABUSE_NOTIFY_EMAIL`.

- **Real database migrations.** `db/schema.sql` (re-run to upgrade) is replaced by [node-pg-migrate](https://salsita.github.io/node-pg-migrate/) with SQL files in `server/migrations/`. Run `npm run migrate` (also `migrate:down`, `migrate:create`). Unlike the old idempotent script, migrations are applied once, tracked in `pgmigrations`, reversible, and may drop, rename and backfill. The first migration is the full v10 schema and is safe on existing databases (it changes nothing and gets recorded), so **upgrading needs just `npm run migrate`**. `MIGRATE_DATABASE_URL` optionally points migrations at a Session/Direct connection. CI now migrates up, down and up again. `docker-compose.yml` no longer auto-loads a schema; run `npm run migrate` after `docker compose up -d db`.

- **Security: webhook SSRF fix.** `webhookUrl` was passed straight to `fetch`, so a user could make the server call localhost, private networks or cloud metadata (`169.254.169.254`), including through redirects. Webhooks now go through `services/ssrf.js`: the host name is resolved once, every address is checked (loopback, private, link-local, CGNAT, multicast, reserved, IPv4-mapped/6to4/NAT64 IPv6; IPv6 is allow-listed to global unicast) and the socket connects to that vetted IP, so DNS rebinding cannot swap it afterwards. Redirects are never followed (a 3xx counts as failed), the response body is never read, there is a 5 s hard timeout, and URLs with credentials or `localhost`/`.local`/`.internal` names are refused. `webhookUrl` is also rejected at save time with a clear error. Alerts no longer delay the visitor's redirect. Existing links with an internal `webhookUrl` stay in the database but are blocked at send time.
- **Safe Browsing re-check on redirect.** Destinations were only checked when a link was saved, so a site listed later kept redirecting. The redirect now looks up the destination it is about to send the visitor to (the matching routing-rule URL, if one applies) and shows a `403` "Link blocked" page when it is flagged. It shares the existing 5-minute cache, so most visits cost no API call; concurrent visits to an uncached URL share one lookup; it uses its own 1.5 s timeout and always fails open, pausing checks for 30 s after a failure so an outage doesn't slow every redirect. Runs before the password form and before a click-limited visit is consumed. New `SAFE_BROWSING_RECHECK_ON_REDIRECT` (default `true`) and `SAFE_BROWSING_REDIRECT_TIMEOUT_MS`.
- **Database: Supabase.** The database is now Supabase Postgres instead of a self-managed Postgres. Queries and the schema are unchanged because Supabase is Postgres and the server already used `pg`, so there is no `supabase-js` and no code change in routes or services. What changed: `db.js` turns TLS on for Supabase hosts and has a pool error handler (a dropped idle connection no longer crashes the process) and a 10 s connect timeout; new optional `DATABASE_SSL`, `DATABASE_SSL_CA`, `DATABASE_POOL_MAX`; `schema.sql` enables Row Level Security (no policies) on every table so Supabase's REST API exposes nothing; `DATABASE_URL` in `.env.example` is a Supabase pooler string. Works with the transaction pooler (port 6543). `docker-compose.yml` stays as an optional offline Postgres. **No data migration:** start on an empty Supabase project and run `server/db/schema.sql`.
