# Changelog

## Unreleased

- **Compare, funnel and CSV export:** new **Compare** page plots 2 to 5 links on one chart (clicks or unique visitors per hour/day) with a summary table. New **Funnel** page shows clicks, unique visitors, returning (2+ clicks) and repeat (3+ clicks) visitors for all links or one link. **Export CSV** on Overview, a link, Compare and Funnel downloads either totals over time or every click (up to 50,000 rows). New endpoints `GET /api/stats/compare`, `/funnel` and `/export` (see docs/API.md). No schema change. The funnel counts people by the keyed IP hash, so it measures repeat visits, not conversions.
- **Bot detection:** the hand-written user-agent regex is replaced by the maintained [`isbot`](https://www.npmjs.com/package/isbot) list (new dependency), which covers search crawlers, link-preview fetchers (WhatsApp, Telegram, Slack, Discord, Facebook, LinkedIn, X), uptime monitors, headless browsers and HTTP libraries (curl, python-requests, Go, axios). A missing User-Agent still counts as a bot. Bots are still not counted, do not use up click limits and get the main destination. To pick up newly seen bots, upgrade the package (`npm update isbot`). Unit tests cover bots and real/in-app browsers.
- **Country tracking and CSV columns:** country was only recorded behind Cloudflare/Vercel/CloudFront, so it was empty everywhere else. It now falls back to an offline lookup of the visitor's IP (new dependency `geoip-country`, ~8 MB; the IP is still never stored). This also makes country routing rules work without a CDN. Behind a proxy set `TRUST_PROXY=1`. Older clicks stay without a country. CSV exports now have separate `date`, `time` and `time_zone` columns, and the click export has `country_code` and `country` name (`Unknown` when not recorded, `Direct` for no referrer).
- **UI:** dark-only redesign with a violet accent, responsive layouts (link cards on phones, collapsible create form).
- **Device and country routing:** a link can carry up to 10 rules that send matching visitors to a different URL, for example iOS visitors to the App Store and Android visitors to Google Play, or visitors from one country to a local page. A rule has a `device` (`ios` or `android`), a `country` (2-letter code) or both; rules are tried in order, the first match wins and everyone else goes to the link's `url`. `POST`/`PATCH /api/links` accept `routes` (`PATCH` replaces all rules, `[]` removes them) and links are returned with `routes`. Rule URLs follow the same rules as `url` (http/https only, no links back to the service or its custom domains). Works with passwords, expiry and click limits. The dashboard has a **Device & country routing** section in the create form and the edit dialog, with a one-click "App Store & Google Play" preset, and a "N routing rules" badge in the list.
- **Webhook and milestone alerts:** links can trigger a webhook or email notification when they are used for the first time, when they hit key click milestones (for example 10, 50, 100 clicks), or when a one-time link is used up. A link can carry an optional `webhookUrl`, `notifyOnClicks` and `notificationEmail`; the payload includes the slug, short URL, click count and event type, and the final click of a one-time link fires exactly once.
- **Routing limits:** device comes from the User-Agent, so iPadOS 13+ Safari (which reports a Mac) and bots get the main destination. Country comes from a CDN header or, failing that, an offline IP lookup. Not part of the CSV import.
- **Schema:** adds `links.routes` (JSONB, default `[]`). **Run `server/db/schema.sql` together with deploying this version**: the redirect now selects that column, so a server without it fails every redirect.
- **Tests:** unit tests for rule validation, rule matching order, device detection from real User-Agent strings, and country headers.
- **Fixed:** unresolved merge conflict markers (from merging the custom-domains work) in `server/src/routes/links.js`, `server/src/services/bulkImport.js`, `server/src/services/linkFields.js`, `server/src/index.js`, `server/test/bulkImport.test.js` and `server/README.md` stopped the server from starting. Resolved in favour of the custom-domains version.
