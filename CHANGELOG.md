# Changelog

## Unreleased

- **Custom domains:** users can add their own domain, verify it with a DNS TXT record (`_linkpulse.<host>` = `linkpulse-verify=<token>`) and put links on it. A request is routed by its `Host` header: a verified custom domain serves only its own links, any other host keeps serving the default domain exactly as before. New endpoints `GET/POST /api/domains`, `POST /api/domains/:id/verify`, `DELETE /api/domains/:id` (with `?deleteLinks=true` when the domain still has links) and the public `GET /api/domains/allowed?domain=` for on-demand TLS (Caddy's `ask`). Links accept `domainId`, are returned with `domainId`/`domain`, and a link's `shortUrl` uses its domain. `GET /api/links` accepts `domain` (id or `none`); CSV import has a `domain` column and a `?domain=` default; the dashboard has a **Domains** dialog, a domain picker and a domain filter. At most 10 domains per user.
- **Slugs are unique per domain**, not globally. `links.slug`'s global unique constraint is replaced by two partial unique indexes (default domain, and per custom domain); existing links stay on the default domain unchanged. The slug cache is now keyed by domain and slug. **Run `server/db/schema.sql` together with deploying this version**: an older server would look slugs up without a domain and could serve a custom domain's link on the default domain.
- **Self-links:** destinations on a verified custom domain are refused, like the service's own host, so a link cannot loop back to the service.
- **Config:** new optional `CUSTOM_DOMAIN_TARGET` (what users should point their domain at; defaults to the host of `BASE_URL`).
- **Schema:** adds the `domains` table and `links.domain_id`.
- **Tests:** unit tests for host validation, TXT verification, the routing check, and the domain column of the CSV import.
- **Folders:** group links into folders (one per link, flat, per user). New endpoints `GET/POST /api/folders` and `PATCH/DELETE /api/folders/:id`. Names are unique per user ignoring case, up to 50 characters, at most 200 folders per user. Deleting a folder keeps its links, which become unfiled.
- **Tags:** links carry up to 10 free-form tags (stored lowercase, up to 32 characters). `POST`/`PATCH /api/links` accept `tags` (array; `PATCH` replaces them) and `folderId` (`null` removes the link from its folder). `GET /api/tags` lists your tags with counts.
- **Filtering and search:** `GET /api/links` accepts `folder` (id or `none`), `tag` and `q` (matches slug, destination or tag). The Links page has a folder filter, tag chips and a search box.
- **Bulk create from CSV:** `POST /api/links/bulk` (`Content-Type: text/csv`) creates up to 500 links per request. Columns: `url` (required), `slug`, `tags`, `folder`, `expires_at`, `password`, `max_clicks`; header names are matched loosely and comma, semicolon or tab delimiters are detected. Valid rows are created, invalid ones are reported by row number. `?dryRun=true` validates without creating, `?folder=` and `?tags=` add defaults. The dashboard has an **Import CSV** dialog with a preview and a downloadable results file that includes the new short URLs.
- **Schema:** adds the `folders` table and `links.folder_id` and `links.tags` (with indexes). Re-run `server/db/schema.sql`; existing links are untouched and start with no tags and no folder.
- **API:** link objects now include `tags`, `folderId` and `folderName`. Malformed JSON and oversized request bodies now return `400`/`413` with a message instead of `500`.
- **Tests:** unit tests for the CSV reader, the bulk import mapping and the link field validators.
- **Docs:** repository links point to https://github.com/ViralJain758/LinkPulse.
