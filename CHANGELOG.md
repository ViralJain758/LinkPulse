# Changelog

## Unreleased

- **Device and country routing:** a link can carry up to 10 rules that send matching visitors to a different URL, for example iOS visitors to the App Store and Android visitors to Google Play, or visitors from one country to a local page. A rule has a `device` (`ios` or `android`), a `country` (2-letter code) or both; rules are tried in order, the first match wins and everyone else goes to the link's `url`. `POST`/`PATCH /api/links` accept `routes` (`PATCH` replaces all rules, `[]` removes them) and links are returned with `routes`. Rule URLs follow the same rules as `url` (http/https only, no links back to the service or its custom domains). Works with passwords, expiry and click limits. The dashboard has a **Device & country routing** section in the create form and the edit dialog, with a one-click "App Store & Google Play" preset, and a "N routing rules" badge in the list.
- **Routing limits:** device comes from the User-Agent, so iPadOS 13+ Safari (which reports a Mac) and bots get the main destination. Country needs a CDN header (Cloudflare, Vercel, CloudFront); without one, country rules never match. Not part of the CSV import.
- **Schema:** adds `links.routes` (JSONB, default `[]`). **Run `server/db/schema.sql` together with deploying this version**: the redirect now selects that column, so a server without it fails every redirect.
- **Tests:** unit tests for rule validation, rule matching order, device detection from real User-Agent strings, and country headers.
- **Fixed:** unresolved merge conflict markers (from merging the custom-domains work) in `server/src/routes/links.js`, `server/src/services/bulkImport.js`, `server/src/services/linkFields.js`, `server/src/index.js`, `server/test/bulkImport.test.js` and `server/README.md` stopped the server from starting. Resolved in favour of the custom-domains version.
